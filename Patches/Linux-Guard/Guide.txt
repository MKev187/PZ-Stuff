Linux-Guard 1.0.0 - Guide
Made by MKev.
==========================================================================

Linux-Guard is OPTIONAL. You only need it on a LINUX dedicated server.
Players and Windows servers do not need it. On any system other than Linux
it changes nothing and just starts the server.


Why?
----
Windows does not care about upper and lower case in file names, Linux does.
Some mods use their files with a different spelling, and Project Zomboid
itself looks up some mod paths completely in lower case (for example
animation files that are linked with x_extends). On Linux these files are
then "not found": errors in the server log, missing animations or recipes.


What does it do at every start?
-------------------------------
1. It checks whether the server runs on Linux. If not: nothing is changed.
2. It checks whether a case fix already exists (links made by another
   script, or a start script that already has its own case fix).
   If everything is already fixed, Linux-Guard does nothing extra.
3. Otherwise it adds lowercase links (shortcuts) next to every mod file and
   folder with capital letters, for example
       media/AnimSets/...  ->  media/animsets/...
   Nothing is renamed, moved, changed or overwritten. The Workshop files stay
   as they are, so Steam updates keep working.
   Folders: <server>/steamapps/workshop/content/108600 and Zomboid/mods
   (the Zomboid folder from -cachedir=... if you use it, else ~/Zomboid).
4. It starts the server exactly like the original start-server.sh of PZ
   (same Java setup, same ProjectZomboid64 call, all your start options).
5. After "SERVER STARTED" it checks once more. Only if mods that the server
   downloaded during this boot needed NEW links, it sends a message to the
   players, waits 60 seconds and restarts the server ONE time ("quit", so the
   world is saved). Never more than one automatic restart per start and per
   hour (loop guard). If nothing new was needed, nothing happens.

Console commands typed in your panel or terminal still reach the server.
A stop signal (Ctrl+C, panel stop) is passed on as "quit", so the world
is saved.


Which case is yours?
--------------------
Case 1 - You can change the start command of your server
  - Create the folder Linux-Guard in the server main folder (the folder with
    ProjectZomboid64 and start-server.sh) and put start-server.sh into it:
        <server>/Linux-Guard/start-server.sh
  - Set the start command to:
        bash Linux-Guard/start-server.sh <your usual start options>
  - The original start-server.sh of PZ stays unchanged. Linux-Guard does the
    case fix and then starts the original. PZ updates do not affect it.

Case 2 - The start command is fixed, but files in the server folder stay
         (many rented game servers)
  - Optional: keep a copy of the original, e.g. start-server.sh.original
  - Replace start-server.sh in the server main folder (next to
    ProjectZomboid64) with the start-server.sh from this folder.
  - After a PZ server update (SteamCMD update or "validate") the original
    file can come back. Check the first lines of start-server.sh: if
    "Linux-Guard" is not in it, copy ours in again.

Case 3 - Docker or a panel creates start-server.sh new at every start
  - Here every change to start-server.sh is lost at the next start.
  - Put the Linux-Guard folder into the persistent volume (the server
    folder that survives a restart, usually the one with steamapps/ and
    Zomboid/ in it).
  - If the image or panel offers a variable for the start command or a
    custom start script, set it to
        bash <volume>/Linux-Guard/start-server.sh <your usual start options>
    Linux-Guard then works like case 1. If the generated start-server.sh
    already brings its own case fix, Linux-Guard sees that and does nothing
    extra.
  - If there is no such setting, a lasting fix is not possible on this host.
    Many of these images already bring their own case fix.


Useful commands (run in the folder of the script)
-------------------------------------------------
  bash start-server.sh --linux-guard-check   only counts missing links, writes nothing,
                                             does not start the server
  bash start-server.sh --linux-guard-undo    removes only the links Linux-Guard made
                                             (links of other tools stay)
  Log: linux-guard.log in the server main folder.


Remove Linux-Guard
------------------
Put back the original start-server.sh (case 2) or the old start command
(case 1 and 3). If you want, run --linux-guard-undo first. The links do no
harm if they stay.


Settings
--------
Nothing has to be set. Optional settings (environment variables or a file
linux-guard.conf next to the script) are listed in README.md.
